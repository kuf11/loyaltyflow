# Безопасность LoyaltyFlow

## Модель доверия

Доверенные компоненты: backend, PostgreSQL и отдельно защищённый admin API. Браузер владельца, Telegram Mini App, параметры URL, request body, заголовки и Telegram-профиль до проверки `initData` считаются недоверенными.

## Обязательные секреты

- `POSTGRES_PASSWORD`: уникальный пароль БД.
- `SYNC_SECRET`: случайное значение не менее 32 байт.
- `ADMIN_KEY`: отдельный случайный ключ не менее 32 байт.
- `JWT_SECRET`: случайное значение не менее 32 байт; используется для подписи сессий и ключевого материала шифрования.
- `TURNSTILE_SECRET_KEY`, `RESEND_API_KEY`, `TELEGRAM_BOT_TOKEN`: хранить только в secret manager/переменных окружения.

Пример генерации:

```bash
openssl rand -base64 48
```

Никогда не помещать реальные значения в Git, HTML, query string, логи или скриншоты.

## Production-проверки

- `ALLOW_DEV_CAPTCHA=false`
- `ALLOW_DEV_EMAIL_CODE=false`
- `AUTO_APPROVE_REGISTRATIONS=false`
- `PUBLIC_APP_URL` использует HTTPS и правильный внешний origin.
- `CORS_ORIGINS` содержит только необходимые HTTPS origins.
- Порты PostgreSQL и admin API не доступны из интернета.
- Логи не содержат кодов подтверждения и Telegram `initData`.
- Выполнены `npm test`, `npm run check` и аудит зависимостей.
- Настроены резервные копии PostgreSQL и проверено восстановление.

## Критические инварианты

1. Клиент не может сам подтвердить оплату или сумму заказа.
2. Баланс изменяется только в транзакции PostgreSQL с блокировкой строки клиента.
3. Повтор одного события оплаты не создаёт повторное начисление.
4. Любая owner-операция фильтруется по `owner_id` из проверенной сессии.
5. Любая Telegram-операция использует валидный, свежий `initData` для нужного бота.
6. Секреты сравниваются безопасно и не возвращаются в ответах.
